# v0.10.0 — Platform integrity floor + adoption foundations

**Released:** 2026-06-23

This release closes out the entire P0 platform-integrity slate
from the 2026-06-11 roadmap rewrite and ships the first half of P2
(adoption). Twelve PRs merged in a single push; master grew from
122 tests to 252 and lost ~1,000 lines of dead code.

The user-visible headline: **the Investigator now reads recent
deploys at preflight time and asks "what changed?" as part of
every investigation.** The internal headline: **the June outage
chain, replayed, would fail the deploy loudly at the first step.**

## Highlights

### Investigator reasons about deploys

A 30-minute scheduled search detects `(service.name,
service.version)` transitions and emits `criblapm_deploy` events
to the dataset (PR #84). The Investigator's preflight then reads
the last 2 hours of those events and seeds them as known signals
(PR #85), so the LLM gets context like:

> **Recent deploys** (last 120 minutes): `service.version`
> transitions detected by the criblapm__deploy_events search.
> "What changed?" is the first RCA question — strongly consider
> whether any of these correlate with the symptoms you're
> investigating:
>
>   - `payment` -> `2.3.0` (12m ago, first seen on 250 spans).
>   - `cart` -> `2.2.0` (45m ago, first seen on 1,800 spans).

No SCM integration needed; the data flows from OTel resource
attributes the platform already carries.

### Low-volume mode (opt-in)

Settings → Workspace → Low-volume mode (PR #81). When on, the
alert evaluator adds a fourth detection arm — `>=2 errors AND
>=1% rate` — for services whose total traffic is too thin to clear
the production-tuned thresholds. **Off by default.** Restores
detection of `llmRateLimit` / `recommendationCache` scenarios on
low-RPS endpoints without re-introducing noise on busier
workloads.

### Platform integrity tripwires (the entire P0 slate)

The June 2026 outage chain — a latent framework change shipping
`dataset=""` into 17 saved searches, plus a `(?i)`-regex bug
writing unjoinable lookup CSVs while reporting success — is now
fenced at four layers:

- **Provisioning guard** (#72) — pre-reconcile static-text check.
  Empty datasets, `(?i)` upstream of export-to-lookup, `mv-expand`
  upstream of export-to-lookup, or empty lookup names cause the
  reconcile to exit 1 before touching the server.
- **Post-reconcile canary** (#78) — after apply, verify a sentinel
  saved search has rows in `$vt_results` and a known lookup is
  joinable end-to-end. Tolerates empty only with `--first-install`.
  **Caught a real Cribl-side bug on staging** — see "Found bug"
  below.
- **Golden-file KQL tests for all 42 query builders** (#79) —
  snapshot drift + the same invariants the guard runs, plus three
  negative regression tests that pin the exact June outage shapes.
  A coverage meta-test fails on any new export that isn't
  registered, so the test surface itself can't drift.
- **Alert state machine extracted to pure TS** (#77) — the KQL
  `case()` chain in `alertEvaluator()` is mirrored by
  `nextAlertState()` with 14 transition tests pinning every arm
  and three full traversals.
- **Framework SHA pin in CI** (#75) — `.framework-sha` recorded
  in-repo. PR #66's latent break (master-tip clone of the
  framework) cannot recur silently.

### Noise budget for threshold tuning

A daily `criblapm__noise_budget` scheduled search (#83) aggregates
per-(service, day) alert-fire counts from the existing alert
history, distinguishing persistent fires (real problems) from
noisy fires (over-sensitive thresholds). Feeds the eval harness so
threshold changes are scored on **precision** alongside recall —
solves the whiplash that PRs #67/#69 surfaced.

## Quality of life

- **Surfaced three swallowed exceptions** (#74) — `agentPreflight`,
  `agentTools.parseArgs`, `notificationTargets`. Failures now log
  to the iframe dev console instead of returning empty results
  indistinguishable from success.
- **Deleted dead `spanmetrics*` builders** (#76) — −198 lines,
  zero callers across `src/` and `tests/`.
- **Deleted legacy `HomePage.tsx`** (#80) — −829 lines, never
  routed; `App.tsx` and `main.tsx` had no references.

## Found bug (Blocked on Cribl)

The post-reconcile canary fired against staging during validation
of #78. The same identical KQL probe against
`criblapm_trace_originators` returns `joined=50` and `joined=0` in
queries seconds apart, with no scheduled-search run between. The
write side reports cleanly. Suspected worker-cache or
read-during-overwrite race on the lookup CSV. Documented in
ROADMAP § Blocked on Cribl (#82); reproduction notes pending for
the Cribl platform team.

## Roadmap state going into v0.11.0

The roadmap was re-priorititized at release time. **Per-signal
datasets** (new P0) is now the top item — metrics support is
landing and metrics/logs may live in datasets distinct from
traces, which the current single-`getCurrentDataset()` design
can't express. **Field mapping** (new P1) is the immediate
follow-on. Detection quality, adoption, and moat work continue
behind those.

See [`ROADMAP.md`](../../ROADMAP.md) for the full list.
