# v0.14.0 — Incidents: the full loop

**Released:** 2026-08-20

This release makes incidents real. Alerts collapse into incidents,
incidents get investigated by an agent, annotated by humans, and
resolve on their own — a complete detect → group → investigate →
annotate → resolve loop, entirely Cribl-Search-native and proven
live end-to-end (twice on staged fault scenarios and once through a
full 14-scenario eval suite).

The user-visible headline: **the Alerts page now leads with
Incidents — the thing you actually drill into — and each incident
has a warroom page that tells the whole story**: what happened, who
was affected, what the AI found (down to the offending source
lines), and everything humans and machines said about it, on one
timeline.

The internal headline: **detection got two new arms** (service-level
p95 latency regression and a reachable silent-service signal), and
a pre-release multi-angle review plus live soak caught and fixed
nine confirmed bugs before tagging.

## Highlights

### Alerts collapse into incidents (#146)

One fault trips alerts across many services; those alerts now roll
into a single stateful **Incident**. Three cooperating scheduled
searches — a grouper (attach via the `criblapm_incidents` lookup +
service-graph adjacency, deterministic ids, idempotent under
retries), an incremental state fold, and a lookup export — run
entirely inside Cribl Search. Incidents open, escalate severity as
membership grows, resolve after all alerts clear (debounced), reopen
on refire, and close after quiet. The investigator cell is pure
enrichment: everything above works with it off.

### The incident warroom page (#147)

`/incident/:id` — summary narrative (root-first ordering, blast
radius, outcome), correlated server-side investigations with their
conclusions and transcript links, member services with per-signal
detail and peak error rates, and an interleaved timeline of system,
agent, and human events. Humans annotate right there: notes, status
and severity overrides, close/reopen — all appended to the same
event log the machines write, via `export to search`. Human status
rules while the incident is active; the system supersedes it with
resolution once alerts clear; a refire reopens (and the UI says so
when you close a still-firing incident).

### Latency detection arm (#147)

The evaluator's service arm fired only on error-rate / silent /
traffic-drop; latency-dominant faults were invisible (the per-op
arm's 250ms floor sits above real regressions on fast services —
recommendation degrades ~45ms → ~140ms and never alerted). New arm:
`curr_p95 >= prev_p95 * 3 AND curr_p95 >= 100ms`, volume-gated,
stream-filter parity with the baseline. Fired naturally within 26
minutes of the fault in live validation.

### Silent arm made reachable (#147)

A fully-down service emits no spans — so it had no evaluator row,
the `curr_requests == 0` case could never match, and its alert state
machine froze. The evaluator now synthesizes zero-request rows for
services present in the service-summary baseline but absent from the
current window, with a fleet-wide storm guard (a collector outage
that silences a third of the fleet is a telemetry problem, not
per-service downtime).

### Server-side investigations: pull-based trigger (#147)

Cribl's saved-search notification dispatch broke workspace-wide
(~Aug 15; platform bug filed). The investigator cell's coordinator
now **pulls**: a durable self-re-arming alarm reads the
`criblapm__alert_notify` search's cached results every 5 minutes
through the same admission/dedup path. The webhook stays wired —
when the platform bug is fixed, push resumes as primary with the
poll as a free backstop. Reading the notify search's results (not
the dataset) preserves the `serverInvestigations` off-switch: flag
off ⇒ search deleted ⇒ poll no-ops. See
[docs/server-side-investigations.md](../server-side-investigations.md).

### Eval harness: incidents-aware (#147)

Five incident-layer checks auto-appended to every alert-firing
scenario, scenario isolation (lingering incidents agent-closed with
propagation wait), server-mode investigator support, and a stack of
locator/timing fixes discovered by running it for real. The full
14-scenario suite ran 11.5 hours against this release's staging
deploy; the resulting findings (detection-margin tiers, the silent
arm bug, wait budgets) are fixed here or tracked in ROADMAP P2.

## Reliability notes

Nine confirmed findings from the pre-tag review are fixed in this
release, including: fold status/severity overrides reduced
latest-by-time (a close-after-reopen could stick an incident open
forever), incident-page scan windows capped at 48h, warroom
timelines keep the newest events when capped, latency alerts now
appear in Overview's Detected Issues, and investigation correlation
uses the cell's index instead of a timeout-prone dataset scan.

## Known limitations

- Autonomous investigations require the celld deploy of this
  release's coordinator (poll trigger + interactive service
  metadata); until then, alerts group into incidents but no
  automated investigation attaches.
- Incident root is the first-firing member; the graph-derived root
  (downstream-most erroring node) lands with P4.4 Phase 4.
- The rolling baseline absorbs a sustained degradation after ~2h
  (the alert self-resolves); a sticky baseline is tracked in
  ROADMAP P2.
- Cribl notification dispatch remains broken workspace-wide on
  staging (platform bug filed); the poll covers it.
