# 2026-10-02 — app-utils 0.12 uptake, provisioning (A3)

First PR of the framework uptake (A3; A4–A8 follow). APM moves to
`@criblio/app-utils@^0.12.1` / `@criblio/app-tooling@^0.4.1` and deletes
its private copies of code the framework now owns.

## What moved to the framework

| APM code (deleted or reduced) | Framework module |
|---|---|
| `src/api/provisionGuard.ts` + test | `/provision-guard`, run by `/provisioner` on every apply path |
| guard block in `scripts/provision.ts` | `planOnly()` / `reconcile()` throw `ProvisionPlanError` |
| body of `src/api/postReconcileCanary.ts` | `/provision-canary` `runProvisionCanary`; the generated-event round trip is an `extraProbes` entry |
| `ensureAlertNotification` / `removeAlertNotification` / `existsFromGet` | `/notifications` `ensureSavedSearchNotification` / `removeSavedSearchNotification` / `ensureNotificationTarget` |
| inline `schedule.notifications` on `criblapm__alert_notify` | `ALERT_NOTIFY_BINDING` (`cellProvisioning.ts`) |
| `src/api/cronOffset.ts` | `/cadence` `offsetCron` |
| `latestRunRows` + `readCachedPanelsRaw` body in `panelCache.ts` | `/vt-results` `readVtResults` / `latestRunRows` |
| private `runWithLimit` in `search.ts` | `/search` `runWithLimit` + `SEARCH_FANOUT_LIMIT` |

## Evidence gathered

- The plan from `getProvisioningPlan()` was dumped from `origin/master` and
  from this branch at all 32 combinations of cadence (1m/2m/5m/10m) ×
  serverInvestigations × metricsEmit × lowVolumeMode. 912 search entries.
  The only difference: the 16 `criblapm__alert_notify` entries lose their
  inline `schedule.notifications`. The server drops that field anyway, and
  the framework diff ignores it. Ids, names, queries, windows and crons are
  identical.
- The framework `offsetCron` differs from the local copy in one input the
  plan never produces. Given an already-offset step (`1-59/5`), the local
  copy returned it unchanged; the framework shifts it again (`3-59/5`). The
  "unchanged shapes" test case moved to an explicit "composes" case. Every
  cadence table and plan-cron assertion passes unchanged.
- `npm run deploy` has no dry-run mode (`cribl-app-deploy` ignores `--dry`
  and deploys). It was not run. `scripts/provision.ts --dry` needs OAuth
  and the staging API, so it does not work offline. An offline `planOnly`
  against a fake empty workspace passes the guard (35 creates).
