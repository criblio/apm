# Traces page UX guidance pass (2026-05-28)

PR G of the v0.9.0 faceted-nav thread. Companion to PRs D/E/F (#46/#47/#48)
which shipped the data layer, UI primitives, and Search-page integration —
all functional, but the page felt "experts-only" without explanatory copy
or a guided empty state.

## What changed

- **Spotlight is now the default rail tab.** Facets is still one click
  away, but for someone actually debugging Spotlight is the higher-
  value primitive — Facets tells them what they already implicitly know,
  Spotlight surfaces what they didn't.

- **Rich empty state on the rail.** When no signal yet, the rail
  explains what Facets vs Spotlight do, and offers three sample-filter
  chips (HTTP 5xx errors, POST requests, gRPC calls) that one-click
  seed a filter row. Brand-new users can see the panel light up
  without guessing attribute names.

- **Per-panel captions.** Both panels lead with a short sentence
  explaining what the bars mean. Spotlight's caption tells the user
  that "the colored bar shows your selection's share of values; the
  gray bar shows the rest of the time window's share. A big gap means
  that attribute is a strong differentiator." That replaces the
  prior unexplained sel/base color coding.

- **Loading states explain themselves.** "Loading facets…" became
  "Loading facets — querying each attribute in parallel; values
  appear as queries return…" so users understand why it streams in.

- **Sidebar hints.** The Filters section now leads with "Narrow the
  spans your search and the side rail will analyze. Suggestions
  appear as you type." so the relationship between the filter
  builder and the rail is explicit.

- **Center banner is richer.** Where the page used to say "Pick a
  service and click Find Traces to begin", it now also tells the
  user that the Spotlight rail works independently — they don't
  need a trace list to explore.
